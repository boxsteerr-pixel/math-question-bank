# v0.5.3 发布前最终独立审计

审计对象为基线 918f5d24bf97a9ddf4ef7611983fe2b8b1b2472b 至候选 6a13e480a358017a161c6257d6f4c95866332642。GitHub main 经比较仍为基线。审计开始时分支 stability-data-safety 的工作区干净。

## 发布结论

**暂缓发布。** HIGH 风险涉及缺少 Web Locks 的浏览器和仍打开的旧版本练习页。候选恢复代码在没有 `navigator.locks` 时直接执行覆盖。即使恢复事务先比较了快照与当前数据库，另一个页面仍可在事务提交后把其内存里的旧任务或草稿写回，覆盖恢复结果。旧版 v0.5.2 页面也没有参与候选版本的会话锁。关闭其他页面的文字提示依赖用户操作，不能阻止竞态。应提供可靠的跨版本写入隔离或在无法保证独占时阻止恢复，并使用真实多页面测试验证。参见 `js/backup.js:183-194`、`js/app.js:31`、`js/app.js:179-186`。

## 独立审查

- 备份预检对各 store 检查主键类型和重复值，检查答题、任务与打卡的部分关联。恢复前快照位于同源独立数据库，写入后会读取比较。恢复事务在提交前逐条比对，并在异常时中止。Node 和实际 Edge 回归覆盖正常恢复与回退，仍需覆盖无 Web Locks 和旧页面同时写入的真实场景。
- 范围不足时任务和出题历史由同一事务保护。但 `getDailyWorkload` 在校验范围之前可能写入 `unfinishedPracticeStartDate`，因此“无任何残留写入”不成立。这是 MEDIUM，可能固定补做启用日期。参见 `js/questionEngine.js:233-235`。
- 异常任务检查会保留草稿、已开始任务及关联打卡，隔离无法安全修复的任务。范围和任务创建测试使用模拟 IndexedDB，真实 Edge 测试覆盖部分业务路径。
- Worker 安装不再自动 skipWaiting，更新请求会检查客户端数量。现有 Edge 测试使用固定 Git 提交中的真实 v34 并覆盖升级、离线和多标签页。Safari 实机和客户端检查与新页面同时打开的竞争窗口未验证。
- 预览页面没有正式学习库清理入口。真实浏览器测试比较操作前后各学习表的内容。
- 题库文件在两个提交之间字节一致，实际两个版本均为 368 条。SHA-256 为 13cdefaeca70001581c0e33cc93ec0f2a5c4194d30cf11b99dac5d4211ec90d5。ID、题面、答案和知识点因此一致。题库版本仍为 2026.10.368，数据库版本仍为 3。
- 恢复测试包含完整内容比较和异常回滚。部分测试夹具调整了原有静态断言以适配新架构，范围限制和旧评分策略的行为断言仍存在。无法仅凭模拟证明全部浏览器的事务和并发行为。
