# 修复前复现

| 编号 | 复现和实际结果 | 根本原因 |
| --- | --- | --- |
| BUG-01 | 在隔离记录中令备份的两条答题记录拥有同一主键。预检显示 2 条，覆盖后只剩 1 条。原记录已被替换，事后条数校验才报错。原测试也未发现同条数内容被篡改的情况。 | 预检只要求主键存在，恢复写入使用覆盖语义，关键校验在提交后执行。 |
| BUG-02 | 在正式题库里仅选择「幂的乘方」得到 1 道题。旧引擎允许写入短任务，页面随后因无法凑足 10 道启动失败。另有 5 次打卡但统计为空的合成样本，可用题超过 10 道仍生成 1 道。 | 界面只检查选项非空。任务与出题历史分开写入，原选择器在可用统计不足时可能留下空位。 |
| BUG-03 | 在隔离生命周期模拟中，v34 完成安装即调用一次 `skipWaiting()`，页面收到 `controllerchange` 就刷新。原浏览器基线的自动迁移过程中也出现导航销毁执行上下文。 | Worker 安装时自动接管，旧页面的刷新条件与答题、草稿和写入状态无关。 |
| BUG-04 | 原预览 HTML 的 `#clear` 使只读断言失败。沿调用检查确认按钮可调用正式学习库的清理函数。复现只做静态核查，没有执行清理。 | 预览模块导入并调用了正式数据库的删除入口。 |
| DOC-01 | README 写 162 道，实际正式 JSON 有 368 道。当前文件同时包含 PDF 页码和 DOCX 段落位置。旧说明还指向无法正常执行的校验脚本。 | README 和旧校验规则仍按单一 PDF 批次维护。 |
